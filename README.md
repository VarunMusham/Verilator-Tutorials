# Verilator Tutorial

Four small, self-contained examples that take a hardware design from a first Verilator build to a
self-checking SystemC model. Each example has an RTL design, a testbench, and a script that builds
and runs everything.

The documentation lives in [`docs/`](docs/00-index.md). Start there.

## Learning path

| Step | Folder       | What you learn                                                                 | Chapter |
|------|--------------|--------------------------------------------------------------------------------|---------|
| 1    | `example/`   | Build and run a SystemVerilog testbench with `--binary`, no C++ needed          | [03](docs/03-example-counter.md) |
| 2    | `spi/`       | RTL self-test, then convert RTL to a SystemC model (`--sc`) and drive it from C++ | [04](docs/04-spi-systemc.md) |
| 3    | `latency/`   | Parameterised pipelines (`generate`), per-type latency, scoreboards            | [05](docs/05-latency-pipeline.md) |
| 4    | `memctrl/`   | Stateful design with a golden memory model and out-of-order response channels  | [06](docs/06-memctrl.md) |

New to Verilator? Read [01 basics](docs/01-verilator-basics.md) and
[02 environment setup](docs/02-environment-setup.md) first.

## Quick start

From an MSYS2 UCRT64 login shell (see [02](docs/02-environment-setup.md) for installation):

```sh
cd /d/verilator/spi
./run_all.sh
```

The script runs the RTL self-test, converts the RTL to SystemC, builds it, and runs it. It ends
with `PASS: all SPI transfers correct (SystemC model)` when everything is correct.

## Repository layout

```
verilator/
├── README.md          this file
├── docs/              tutorial chapters (start at docs/00-index.md)
├── example/           counter + SystemVerilog testbench (--binary)
├── spi/               SPI master: RTL self-test + SystemC conversion
├── latency/           per-datatype latency pipeline
└── memctrl/           memory controller with transaction latency
```

Each unit folder follows the same layout:

```
<unit>/
├── rtl/        design files
├── tb/         Verilog/SystemVerilog testbench        (spi, latency, memctrl)
├── sc/         SystemC testbench for the generated model (spi, latency, memctrl)
├── run_all.sh  builds and runs everything
├── obj_*/      build output (generated; can be deleted and rebuilt)
└── README.md   design notes and checks for that unit   (spi, latency, memctrl)
```

## Notes

- The `obj_*` folders and `spi/spi_sc.vcd` are build or simulation output that was committed to git
  in the baseline commit. They are regenerated by the scripts. See
  [09](docs/09-troubleshooting-and-next-steps.md) for the cleanup decision.
- The scripts hard-code `/c/msys64` and `/c/systemc/systemc-2.3.3`. Edit the top of each `run_all.sh`
  if your install is elsewhere.
